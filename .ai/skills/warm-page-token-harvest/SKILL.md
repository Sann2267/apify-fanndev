# Warm-Page Bootstrap Token Harvest

> **The breakthrough that unlocked full-anon GraphQL on Meta (IG/FB/Threads) and Twitter/X.** First request hits the real entity page (a profile, a post, a search) — the HTML carries inline JS bootstrap tokens that authenticate subsequent GraphQL POSTs.

## Problem

Modern SPAs (Meta Polaris/Comet/Barcelona, Twitter, TikTok) gate their internal GraphQL/REST endpoints behind tokens generated by the **first page load**. Hitting the API directly returns 401/403/empty. The tokens are:
- Short-lived (5–30 min)
- Tied to a specific cookie jar (CSRF anti-forgery)
- Sometimes tied to the specific entity URL (per-page LSD token, not per-session)

You can't hardcode them and you can't login. But you can scrape them from the SSR HTML and replay.

## Solution: warm → harvest → replay

### Step 1: Warm the SPECIFIC entity URL (not the root)

```python
# WRONG — warming the root gives a generic LSD that gets rejected for some doc_ids
warmup_url = "https://www.instagram.com/"

# RIGHT — warm the URL of the entity you're about to query
warmup_url = f"https://www.instagram.com/p/{shortcode}/"   # for post-detail
warmup_url = f"https://www.instagram.com/{username}/"      # for account
warmup_url = f"https://www.facebook.com/{page_slug}/"      # for FB page
warmup_url = f"https://www.threads.com/@{username}"        # for Threads profile

r = session.get(warmup_url, impersonate="chrome131")
html = r.text
```

### Step 2: Extract bootstrap tokens from inline JS

The Meta family ships tokens in a `__bbox` / Relay payload + isolated regex-friendly literals.

```python
import re, json

def harvest_meta_tokens(html: str, cookies: dict) -> dict:
    """Returns the bag of tokens needed for POST /api/graphql/"""
    tokens = {}
    
    # LSD = anti-XSRF nonce, per-page-load
    m = re.search(r'"LSD",\[\],\{"token":"([^"]+)"\}', html)
    if m: tokens["lsd"] = m.group(1)
    
    # jazoest — derived integer
    m = re.search(r'"jazoest":"(\d+)"', html)
    if m: tokens["jazoest"] = m.group(1)
    
    # haste_session + client_revision (used in __hs and __rev fields)
    m = re.search(r'"haste_session":"([^"]+)"', html)
    if m: tokens["__hs"] = m.group(1)
    m = re.search(r'"client_revision":(\d+)', html)
    if m: tokens["__rev"] = str(m.group(1))
    
    # __spin_r/__spin_t for the polaris router
    m = re.search(r'"__spin_r":(\d+)', html)
    if m: tokens["__spin_r"] = str(m.group(1))
    m = re.search(r'"__spin_t":(\d+)', html)
    if m: tokens["__spin_t"] = str(m.group(1))
    
    # From cookie jar (set by the warmup response)
    tokens["csrftoken"] = cookies.get("csrftoken", "")
    tokens["mid"] = cookies.get("mid", "")
    tokens["ig_did"] = cookies.get("ig_did", "")
    
    return tokens
```

### Step 3: Replay POST `/api/graphql/` with all the tokens

```python
def build_graphql_form(tokens: dict, variables: dict, doc_id: str, friendly_name: str) -> dict:
    """Build the urlencoded form body for Meta /api/graphql/"""
    return {
        "av": "0",                # anonymous viewer id
        "__user": "0",
        "__a": "1",
        "__req": "a",             # request counter, can be any short token
        "__hs": tokens["__hs"],
        "__rev": tokens["__rev"],
        "__s": "abc:def:ghi",
        "__hsi": "0",
        "__dyn": "",              # router config, can be empty
        "__csr": "",
        "__comet_req": "7",
        "lsd": tokens["lsd"],
        "jazoest": tokens["jazoest"],
        "__spin_r": tokens["__spin_r"],
        "__spin_b": "trunk",
        "__spin_t": tokens["__spin_t"],
        "fb_api_caller_class": "RelayModern",
        "fb_api_req_friendly_name": friendly_name,
        "variables": json.dumps(variables),
        "doc_id": doc_id,
    }


HEADERS_GRAPHQL = {
    "x-ig-app-id": "936619743392459",       # IG; FB uses different app_id; Threads = 238260118697367
    "x-asbd-id": "129477",
    "x-csrftoken": tokens["csrftoken"],
    "x-fb-lsd": tokens["lsd"],
    "x-fb-friendly-name": friendly_name,
    "Content-Type": "application/x-www-form-urlencoded",
    # fb_dtsg NOT needed for read queries (anon viewers don't get one).
}

resp = session.post(
    "https://www.instagram.com/api/graphql",
    data=build_graphql_form(tokens, variables, doc_id, friendly_name),
    headers=HEADERS_GRAPHQL,
)
```

## Variant: Twitter/X guest-token flow

X uses a different bootstrap — guest token activation, not warm-page harvest. But the principle (extract token, then replay) is the same.

```python
# Step 1: activate guest token
r = session.post(
    "https://api.twitter.com/1.1/guest/activate.json",
    headers={"authorization": f"Bearer {PUBLIC_BEARER}"},
)
guest_token = r.json()["guest_token"]  # TTL ~2-4h, rotate on 401/403

# Step 2: harvest queryId + bearer + feature switches from the JS bundle
r = session.get("https://x.com/home", impersonate="chrome131")
bundle_url = re.search(r'(https://abs.twimg.com/responsive-web/client-web/main\.[a-f0-9]+\.js)', r.text).group(1)
bundle = session.get(bundle_url).text

# Regex 158 operations out of the bundle:
ops = {}
for m in re.finditer(
    r'queryId:"([A-Za-z0-9_-]+)",operationName:"(\w+)",operationType:"\w+",'
    r'metadata:\{featureSwitches:\[([^\]]*)\],fieldToggles:\[([^\]]*)\]\}',
    bundle,
):
    qid, name, fs_raw, ft_raw = m.groups()
    ops[name] = {
        "queryId": qid,
        "features": [s.strip('"') for s in re.findall(r'"([^"]+)"', fs_raw)],
        "fieldToggles": [s.strip('"') for s in re.findall(r'"([^"]+)"', ft_raw)],
    }

# Step 3: replay GET /graphql/{queryId}/{operationName}
op = ops["UserByScreenName"]
features = {k: (False if k in FALSE_FORCED_FEATURES else True) for k in op["features"]}
field_toggles = {k: False for k in op["fieldToggles"]}
params = {
    "variables": json.dumps({"screen_name": "jack", "withSafetyModeUserFields": True}),
    "features": json.dumps(features),
    "fieldToggles": json.dumps(field_toggles),
}
r = session.get(
    f"https://api.twitter.com/graphql/{op['queryId']}/UserByScreenName",
    params=params,
    headers={
        "authorization": f"Bearer {PUBLIC_BEARER}",
        "x-guest-token": guest_token,
        "x-twitter-client-language": "en",
        "x-twitter-active-user": "yes",
        "Origin": "https://twitter.com",
    },
)
```

### `FALSE_FORCED_FEATURES` (Twitter)

Even though these appear in the bundle's `featureSwitches` list, they must be `False`:

```python
FALSE_FORCED_FEATURES = {
    "verified_phone_label_enabled",
    "responsive_web_graphql_skip_user_profile_image_extensions_enabled",
    "responsive_web_enhance_cards_enabled",
    "tweet_awards_web_tipping_enabled",
    "responsive_web_media_download_video_enabled",
    "responsive_web_grok_show_grok_translated_post",
    "responsive_web_grok_community_note_auto_translation_is_enabled",
}
```

## Caveats

- **Tokens rot every 2–4 weeks.** doc_id and queryId values change when Meta/Twitter redeploys. Cache + refresh on first 400/404 (trust-but-verify).
- **Warm-page URL must match the entity.** Warming `/` and then asking for `/p/<shortcode>/` data sometimes fails — Meta keys some tokens to the route's React component.
- **Cookie jar is sticky-required.** The CSRF cookie from warmup must be present on the POST. Don't share session across workers.
- **`fb_dtsg` is for write actions only.** Read-only queries (profile lookup, post fetch) work without it. Don't try to harvest it — anon viewers can't.
- **Embed fallback (`/p/<shortcode>/embed/captioned/`) returns `{_error:"no_anon_data"}`** when anon DC IP — IG removed SSR data from embed since 2025.
- **Twitter `TweetDetail` and `SearchTimeline`** are login-walled (guest token returns 404). For general keyword search, degrade to `from:USER keyword` → `UserTweets` + client-side filter.
