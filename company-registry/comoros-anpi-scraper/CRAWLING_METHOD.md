# Crawling Method — Comoros ANPI

**Last verified:** 2026-08-27

## Which registry, and why not RCCM/OHADA

Comoros has no country-specific "Guichet Unique" portal distinct from its
investment-promotion agency, and it is **not** a member state of OHADA (the
Francophone-Africa regional legal/business harmonization body that runs the
shared RCCM system many neighboring countries use) — so there is no regional
RCCM portal to check for Comoros data either. The closest thing to an
official, public, online company registry is the **ANPI (Agence Nationale
pour la Promotion des Investissements)**'s own "Annuaire des entreprises"
(business directory) at `investcomoros.net`. ANPI is the government body
responsible for business registration (including RCCM registration) in
Comoros, and this directory is the one place its own register is exposed
publicly online.

## robots.txt

```
# hestiacp autogenerated robots.txt
User-agent: *
Crawl-delay: 10
```

Fetched directly with `curl_cffi` (`chrome124`), not just via a summarizing
tool, to check the literal text. One `User-agent: *` group, **no
`Disallow` line of any kind**, no mention of Claude/ClaudeBot/anthropic-ai/
GPTBot/AI crawlers anywhere. The only directive is `Crawl-delay: 10`, which
this actor honors literally (see "Rate limiting" below) rather than ignoring
it because it isn't a hard block.

## WAF / anti-bot

**None observed.** The site is a WordPress install on HestiaCP-managed
shared hosting behind plain `nginx` — no Cloudflare/`cf-ray`, no CAPTCHA, no
challenge page, on any request during recon. `curl_cffi` `chrome124` is used
for portfolio-wide consistency, not because a plain `requests`/`httpx`
baseline was observed to fail (recon started directly with `curl_cffi` per
this project's default stack).

## The API: WordPress REST route, no login, no nonce needed for reads

The directory page (`/annuaire-des-entreprises/`) is an Elementor page. Its
search widget is not server-rendered — it's a small vanilla-JS module
(`wp-content/plugins/anpi-annonces/assets/js/frontend.js`) that fetches from
a custom REST route the same plugin registers:

```
GET https://www.investcomoros.net/wp-json/anpi/v1/annonces
    ?search=<text>&ile=<island>&secteur=<sector>&annee=<year>
    &rccm=<rccm>&siege=<city text>&orderby=<nom|annee>&order=<ASC|DESC>
    &page=<1-based>&per_page=<n>
```

This route was found by fetching the directory page's HTML with
`curl_cffi` and grepping for `wp-json`/`ajax`/`fetch(` — it turned up
`var ANPI_CONFIG = {"rest_url": "...wp-json/anpi/v1/annonces", "nonce":
"..."};`, then confirmed by reading the plugin's own `frontend.js`, which
builds the query string and sends the nonce as an `X-WP-Nonce` header.

**The nonce is not actually required for `GET`** — a bare `curl_cffi`
request with no `X-WP-Nonce` header and no cookies at all returns the
identical 200 JSON payload. WordPress REST routes register their own
`permission_callback`; this one is evidently public. This was confirmed by
simply omitting the header and comparing responses, not by guessing.

Response shape: `{"total": <int>, "pages": <int>, "data": [<row>, ...]}`,
where each row is `{id, nom, rccm, ile, secteur, annee, siege, ville,
dirigeant, capital, forme_juridique, description, date_creation,
date_maj}`. This is a clean, flat JSON shape — no HTML/tree parsing needed,
unlike most other actors in this portfolio.

### Pagination

`total`/`pages` are returned up front on every request, so this actor
doesn't blind-paginate — it fetches page 1, reads `total`, computes exactly
how many more pages are needed to satisfy `maxResultsPerQuery`, and fetches
only those. An out-of-range `page` (tested with `page=9999`) returns HTTP
200 with `data: []`, a clean, safe end-of-results signal if ever needed.

`per_page` is **server-capped at 200** — requesting `per_page=500` still
returns only 200 rows per page (verified: the `pages` count in the response
recalculates against the 200 cap, not the requested value). This actor
never requests more than 200 per page.

## Critical data-quality finding: several UI filter fields are always empty

The directory's own search UI (visible in the page HTML before any JS runs)
offers filters for RCCM number, sector, and headquarters city, implying
those fields are populated. To check this, every one of the 6,376 records
was sampled (all 32 pages at `per_page=200`, iterated with the
rate-limited client) and every value of `rccm`, `secteur`, `capital`,
`dirigeant`, and `ville` was inspected:

**All five fields are the empty string on every single record, with zero
exceptions.** Only `nom`, `ile`, `annee`, `siege`, and `forme_juridique`
(plus the internal `id`/`date_creation`/`date_maj`) are ever populated.

This means `secteur=commerce` (or any sector) and any non-blank `rccm`
filter reliably return 0 results today — not a bug in this actor, and not
a bug in ANPI's API either; it's simply that ANPI has not yet back-filled
those fields for the directory it publishes. This actor still passes these
filters through (in case ANPI populates the data later) and does raw
passthrough of whatever the API returns — it does not fabricate or infer
values for the empty fields. Documented here and in the README so a run
returning empty `rccm`/`secteur`/`capital`/`dirigeant`/`ville` on every
record reads as expected behavior, not a scraping failure.

## No per-entity detail endpoint

`GET /wp-json/anpi/v1/annonces/<id>` returns HTTP 404
(`{"code":"rest_no_route", "message":"Aucune route correspondante...",
"data":{"status":404}}`). There is no separate detail route — the list
endpoint already returns every field the plugin tracks per company, so
there's nothing more to fetch per match.

## Rate limiting: honoring `Crawl-delay: 10` literally

Because robots.txt names an explicit `Crawl-delay: 10` (unlike most other
actors in this portfolio, whose targets have no crawl-delay or a fully
commented-out template robots.txt), this actor implements a process-wide
async rate limiter (`client.py`'s `_RateLimiter`) that paces **every**
outgoing HTTP request to `investcomoros.net` at least 10 seconds apart,
regardless of `maxConcurrency` or how many jobs/pages are queued. This
means `maxConcurrency` bounds how much work is queued, not the actual
request rate, which never exceeds 1 request per 10 seconds. A full-directory
pull (`maxResultsPerQuery` near 6,400, ~32 pages) takes roughly 5-6 minutes
as a result — this is a deliberate trade-off in favor of being a good
citizen on a small government site's shared hosting, not a performance bug.

## Sample queries tested during recon

- `search=SARL` — 2,786 matches, mixed islands/years/legal forms, e.g.
  `"BECIP2D" SARL` (Grande Comore, 2020, Foumbouni).
- `search=zzzznonexistentxyz999` — 0 matches, confirms the clean
  `total: 0` "no results" path (no error, no crash).
- No filters at all (full browse) — `total: 6376`, first page returns
  the same 200-row page repeatably.
- `ile=anjouan`, `ile=moheli`, `annee=2024`, `siege=Moroni` — all confirmed
  narrowing the result set as expected (see table above).
- A 250-result pull (spanning pages 1 and 2 at `per_page=200`) confirmed
  the multi-page fetch path returns exactly 250 rows with no duplicates or
  gaps at the page boundary.

## Known limits

- `rccm`, `secteur`, `capital`, `dirigeant`, `ville` are empty on every
  record in ANPI's own data as of this writing (see data-quality section
  above) — not something this actor can fix, since it only reflects what's
  publicly on file.
- `maxResultsPerQuery` is capped at 6,400 (comfortably above the current
  6,376-record total) via a `MAX_PAGES_PER_JOB` safety cap independent of
  the requested max, in case the directory grows substantially between
  verifications.
- The `Crawl-delay: 10` pacing means large pulls are intentionally slow
  (see above) — this is a deliberate choice, not a bug.

## Diff cadence

Quarterly smoke test recommended. This is a small custom WordPress plugin
maintained by (or for) a national government agency — low change velocity
expected, but a redesign of the directory page or a plugin update could
change the REST route path or response shape without notice.
