# Crawling method — Shopee Seller Profile & Performance Scraper

All figures measured 2026-09-20, plain HTTP from one residential IP,
`curl_cffi` with TLS impersonation, no browser, no login.

## The gate, for context

Most of Shopee's API is refused at the load balancer:

```
HTTP 403
{"is_customized":false,"is_login":false,"action_type":2,"error":90309999,…}
header: sgw-errmsg: Status generated by alb
```

Earlier recon tried **19 TLS profiles across 8 country domains** on
`search_items` — all 403, identical body. A homepage warm-up (200, 664 KB)
leaves the cookie jar **empty** and the next API call still 403s, which rules
out a session dance. `get_shop_detail` sits outside that gate.

## Two bugs this build hit, both found by testing rather than reasoning

**1. A minimum-size floor swallowed the error case.** The client originally
required both a parseable body **and** ≥200 bytes. The `invalid_username`
reply is **48 bytes**, so it failed the floor, got retried four times, and
surfaced as a transport error — destroying exactly the signal the Actor exists
to report. Fixed: a parsed dict is an answer regardless of length; the size
floor now applies only to bodies that did not parse.

**2. `response_time` is in seconds, not minutes.** `samsung.official` reports
`102`. Treating that as minutes would have described a shop that replies in
under two minutes as taking an hour and a half. Both units are returned.

## Field notes

- `ctime` — shop creation, Unix seconds. `samsung.official` → 1516089696 →
  3,169 days old.
- `rating_star` — float with full precision (`4.895646`), not rounded.
- `rating_good` / `rating_normal` / `rating_bad` — three separate counters;
  `positiveRatingPercent` is derived from their sum.
- `response_rate` — present on active shops, **absent** on some (e.g.
  `shopee_id`), so it is returned as `null` rather than `0`. Those are not the
  same thing for a supplier-qualification decision.
- `item_count` is `0` on several official-looking shops (`shopee_id`,
  `tokopedia`), so it is not a reliable proxy for catalogue size on its own.

## Shop ID extraction from product URLs

Shopee product URLs carry both IDs: `…-i.<shopId>.<itemId>`. The parser reads
the shop ID from that pattern, which lets the Flash Sale Monitor's output be
piped straight in — that Actor emits product URLs in exactly this form.

## Related actors in this portfolio

`shopee-shop-scraper` extracts a shop's **product catalogue**. This Actor
extracts the shop's **performance metrics** — no overlap in output. Search,
product detail and campaign microsites are covered by `shopee-search`,
`shopee-product-detail` and `shopee-campaign`.
