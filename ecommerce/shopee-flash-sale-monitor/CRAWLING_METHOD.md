# Crawling method — Shopee Flash Sale & Price Drop Monitor

All figures measured 2026-09-20, plain HTTP from one residential IP,
`curl_cffi` with TLS impersonation, no browser, no login.

## The gate, and where it stops

Shopee refuses most of its API **at the load balancer**, before app logic:

```
HTTP 403
{"is_customized":false,"is_login":false,"action_type":2,"error":90309999,"tracking_id":"…"}
header: sgw-errmsg: Status generated by alb
```

Confirmed refused this run:

| Endpoint | Status |
| --- | --- |
| `/api/v4/search/search_items` | 403 on `chrome124` and `safari17_0` |
| `/api/v4/item/get_ratings` | 403 |
| `/api/v2/item/get_ratings` | 403 |
| `/api/v4/shop/get_shop_seo` | 403 |
| `/api/v4/flash_sale/flash_sale_batch_get_items` | 403 |

Earlier recon (2026-09-07) tried **19 TLS profiles across 8 country domains** on
`search_items` — all 403, identical body. It is not a fingerprint problem.

**No `Set-Cookie` is ever issued.** A session that loads `shopee.co.id` first
(200, 664 KB) and *then* calls `get_ratings` still gets 403, with an empty
cookie jar. There is no session dance to discover; the gate wants a
JS/WASM-computed token.

## Session fields

```
banner, banner_url, carousel_banner, categories, description, end_time,
is_ongoing, name, pc_banner, promotionid, signature, start_time, status,
tracker_info, with_mega_sale_session
```

`start_time` / `end_time` are Unix seconds; the extractor converts to UTC ISO.

## Item fields and the money problem

Items carry `itemid`, `shopid`, `name`, `price`, `price_before_discount`,
`discount`, `flash_sale_stock`, `historical_sold`, `image`, `flash_catid`,
`item_rating`, `is_mart`, `start_time`, `end_time`.

**Prices are integers scaled by 100,000.** Measured:

| Raw `price` | Raw `price_before_discount` | Reported `discount` |
| --- | --- | --- |
| `45955000000` | `75800000000` | `-39%` |

459,550 ÷ 758,000 = 0.606, a 39.4% cut — which matches. The divisor is
confirmed by the platform's own discount figure, not assumed.

`discount` arrives as the string `"-39%"`. The extractor returns
`discountPercent: 39.0` as a positive number.

## Paging

`limit=16` returns 16, `limit=100` returns 53. The cap is the session's real
size, so one request retrieves a whole session and `offset` is unnecessary.
`offset=16` returns a full page again rather than the tail, so it is not used.

## Why `Gated` is a separate exception from `Blocked`

Retrying a load-balancer refusal through a four-rung TLS ladder is wasted
compute — the body is byte-identical every time. The client raises `Gated`
immediately on `error 90309999` or a bare 403, and only cycles the ladder for
genuine transport failures. The Actor then emits a `GATED` record naming the
endpoint so the operator can act (residential proxy) instead of seeing an empty
dataset.

## Product Q&A does not exist as a public surface

Four documented-looking paths, all **404 `error_not_found`** (not 403 — the
route itself is absent):

```
/api/v4/pdp/qa/get_qa_list
/api/v4/item/get_qa
/api/v4/qna/get_question_list
/api/v4/pdp/buyer_qa/get_question_list
/api/v4/pdp/get_pdp_qa
/api/v4/item/qa_list
/api/v2/item/qa
```

A "Shopee Q&A extractor" has nothing to extract from over HTTP.

## Product page SSR has closed since the last recon

The 2026-09-07 note recorded the product page as fully server-rendered
(~866 KB with price, stock and rating baked in). Re-measured today:
**848 KB with 0 `itemid`, 0 price fields, 0 `rating_star`, 0 JSON-LD.** The
page is now a shell. Any Actor relying on product-page SSR needs re-testing
before it is trusted.
